# Predictions: mobile

## About agent 'layout'
I predict the layout agent concluded that the CSS Grid architecture in `ide.css` is overly rigid -- the 4-column `grid-template-columns` with hardcoded pixel values (`48px 280px 4px 1fr`) does not adapt gracefully across breakpoints, and the separate mobile media query essentially rewrites the entire grid into a different layout (single-column with rows) rather than letting the grid flex naturally. They likely flagged that the sidebar width should use `clamp()` or `minmax()` to absorb viewport pressure, that the desktop-to-mobile transition creates two completely different layout systems instead of one parametric grid, and that viewport height handling is fragile because `100vh` vs `100dvh` causes the bottom panel and status bar to tuck behind mobile browser chrome. They probably recommended consolidating into fewer grid definitions that degrade gracefully, using CSS custom properties for column sizing, and switching all `vh` units to `dvh` with a fallback.

## About agent 'components'
I predict the components agent concluded that the IDE shell has significant duplication and missing abstractions -- particularly that the resize handle logic (bottom panel and sidebar both implement mousedown/mousemove/mouseup independently in `IDEShell.js`), the panel show/hide patterns (sidebar collapse, bottom panel collapse, drawer toggle all use slightly different mechanisms), and the scroll containment setup are repeated without a shared primitive. They likely proposed extracting a `ResizablePanel` component, a `CollapsibleRegion` or toggle-visibility primitive, and a set of design tokens (the CSS custom properties in `ide.css` are a good start but inconsistently applied -- some colors and sizes are hardcoded inline rather than using the variables). They probably also noted that `CommandBar.js`, `Drawer.js`, `DiffPanel.js`, and `LogCapturePanel.js` each independently manage their own visibility state and keyboard dismiss logic rather than sharing a composable overlay/popover pattern, and recommended a small set of shared primitives: overlay/backdrop, resizable split, scrollable panel, and a token system for spacing/sizing that currently only partially exists in the CSS variables.
