# Predictions: components

## About agent 'layout'

I predict the layout agent identified that the CSS Grid architecture in `ide.css` is reasonably well-structured at the top level (4-column x 3-row outer grid with named areas for titlebar, activity bar, sidebar, resize handle, editor, and status bar) but suffers from a split personality: the outer grid is clean and declarative, while the inner layout of the editor column (tab bar, breadcrumb, editor-area, bottom-panel) relies on a nested flexbox column with manual height calculations and resize-handle JS rather than a nested subgrid or second CSS Grid. They likely flagged the `100vw`/`100vh` sizing as problematic -- the desktop layout uses `100vw` which does not account for scrollbar width and `100vh` which does not account for mobile browser chrome (the mobile media query patches this with `100dvh`, but desktop still uses `100vh`). The sidebar collapse mechanism toggling `grid-template-columns` between `var(--sidebar-width)` and `0px` is functional but brittle because the `display: none` override fights with the mobile `transform: translateX` approach, creating two completely different collapse codepaths. They probably proposed consolidating the editor-column internals into a proper CSS Grid (rows: tabbar | breadcrumb | 1fr editor-area | panel) and replacing the JS-driven panel resize with CSS `grid-template-rows` manipulation, which would eliminate the manual height bookkeeping in `IDEShell._initPanelResize()`.

## About agent 'mobile'

I predict the mobile agent found that the single `@media (max-width: 768px)` breakpoint handles the portrait-to-landscape transition reasonably well for phones but has a dead zone for tablets (768-1024px) where the desktop 4-column grid renders but the sidebar is too narrow to be usable. They likely identified that the sidebar overlay (`position: fixed`, `transform: translateX(-100%)`) works but has scroll containment issues -- when the sidebar is open, touches on the backdrop still propagate to the canvas underneath because the backdrop only covers above the activity bar (`bottom: 48px`) and `touch-action: none` on `html, body` is overridden to `touch-action: auto` in the mobile media query, meaning scroll events can leak through during sidebar transitions. The `!important` overrides on `#canvas` width/height (`width: 100% !important; height: 100% !important`) suggest there were past fights with inline styles from the Three.js renderer, and this is a symptom rather than a fix. They probably also noted that portrait orientation has no dedicated handling -- there is no `@media (orientation: portrait)` query, so a landscape tablet and a portrait phone at similar widths get identical treatment despite very different aspect ratios and interaction patterns. The activity bar's horizontal scroll on mobile (`overflow-x: auto; scrollbar-width: none`) silently clips buttons if there are more than ~7-8 panel icons, with no visual affordance that more exist off-screen.
