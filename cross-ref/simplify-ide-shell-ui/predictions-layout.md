# Predictions: layout

## About agent 'components'

I predict the components agent concluded that IDEShell.js is a monolithic orchestrator doing too much: it manually queries dozens of DOM IDs (sidebar, tabs, panels, status bar items), injects panel HTML via string templates from Drawer.js/DiffPanel.js/LogCapturePanel.js, and handles all wiring (resize, keyboard, activity bar switching) in one 800+ line class. They likely recommended extracting self-contained components -- a TabBar, StatusBar, SidebarPanel, and BottomPanel -- each owning their own DOM creation, event wiring, and state, following the pattern CommandBar.js already uses. They probably also flagged that CSS design tokens are inconsistently applied: some components reference `--text-primary` while others use inline hex values (the groups panel styles in ide.css use `var(--surface-2, #333)` and `var(--border, #333)` which are fallbacks for tokens that are never actually defined in `:root`), and that the `_buildDrawerHTML`-style string template pattern in Drawer.js should converge with the `createElement`-based approach in AppShell.js for consistency.

## About agent 'mobile'

I predict the mobile agent found the same `100vh` bug I identified (line 68 not using `dvh`) and the landscape phone overflow where the bottom panel's 600px JS clamp exceeds the viewport height on wide-but-short screens that bypass the 768px media query. They likely flagged that TouchController.js has no gesture for rotation or double-tap-to-zoom, that `touch-action: none` on the root `html,body` (ide.css:56) blocks all native scrolling including in the sidebar file tree and bottom panel log output (the mobile override to `touch-action: auto` at line 1016 only partially fixes this since canvas touch events call `e.preventDefault()` unconditionally), and that the sidebar overlay's `bottom: 48px` magic number breaks if the status bar or activity bar sizing changes. They probably also noted the absence of a portrait tablet breakpoint between 768px and 1024px, and that the command palette and status bar have no mobile-specific touch target sizing.
