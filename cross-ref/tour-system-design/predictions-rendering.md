# Predictions: rendering

## Parsing Agent
I expect the parsing agent concluded that tour definitions need a structured data format mapping source-level cross-references (function calls, imports, class hierarchies) to grid coordinates and line/column ranges, likely proposing a JSON schema with `{ sourceFile, sourceLine, sourceCol, targetFile, targetLine, targetCol, relationship }` entries that get resolved at runtime against loaded CodeGrids via `SemanticInfoMap` lookups or `_lineSlotBase` mappings. Their key concern is likely the resolution gap between static parse data (file paths, line numbers) and dynamic runtime state (which grids are loaded, their buffer slot indices, their world positions) -- they probably proposed a two-phase approach where raw cross-ref data is parsed first, then resolved against live grid state when a tour is activated. I expect they also addressed how to handle missing grids (file not loaded) gracefully and considered leveraging the existing `userData.sourcePath` on CodeGrid for file-to-grid resolution, possibly proposing a lookup index keyed by source path.

## Orchestration Agent
I expect the orchestration agent concluded that the tour system needs a central `TourController` or `TourPlayer` class that manages step sequencing, camera animation between stops, and coordinates the apply/clear lifecycle of visual annotations per step -- essentially extending the existing `tour.create`/`tour.stop`/`tour.play` command pattern in `navigationCommands.js` to support cross-reference connections rather than just single-grid camera stops. Their key concern is likely the async coordination problem: camera animation is Promise-based (`animateCamera`), highlight application and connection drawing need to happen at specific moments (after camera arrives, before next step begins), and the virtualizer may cull grids mid-tour requiring re-evaluation. I expect they proposed that the orchestrator receives parsed cross-ref data from the parsing agent and rendering primitives (ConnectionRenderer, highlight calls) from my output, wiring them together through the existing command router system with new `tour.crossref.*` commands, and that they focused heavily on step transition timing, cancellation support (aborting a playing tour), and state cleanup to avoid leaked highlights or orphaned connection lines.
