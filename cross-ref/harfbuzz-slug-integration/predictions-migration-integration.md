# Predictions: migration-integration

## shaping-pipeline

I expect shaping-pipeline concluded that HarfBuzz WASM initialization is best done eagerly on workers during the loading screen to avoid first-job latency, and that font ArrayBuffer transfer follows the existing UV map caching pattern in WorkerBridge (one-time transfer per worker, cached with a `_hasFont` flag). They likely flagged that the shaped output must flow through buffer builders as an array of `{glyphId, advance, xOffset, yOffset, cluster}` structs, and that the instance attribute layout stays at 10 floats/40 bytes per glyph -- no new attributes needed because glyph identity is already encoded via `instanceCodepoint` (which would now map to HarfBuzz glyph IDs rather than Unicode codepoints). Their key concern is likely the WASM-in-workers path: `WebAssembly.instantiate` works in workers but adds ~50ms compile time, and they probably recommended pre-warming or `WebAssembly.compileStreaming` with a shared `WebAssembly.Module` transferred to all workers to avoid compiling the same WASM three times.

## shader-rendering

I expect shader-rendering concluded that the Slug fragment shader port to GLSL ES 3.00 is feasible but identified ALU cost as the primary risk -- specifically that per-pixel bezier evaluation across 10K instanced quads could exceed the fragment shader budget on mobile GPUs. They likely proposed a band-based spatial subdivision (horizontal and vertical bands per glyph) to enable early-exit and reduce the number of curves evaluated per pixel from O(n) to O(k) where k is small. They probably recommended two new DataTextures (curve control points as HALF_FLOAT, band indices as UNSIGNED_SHORT) looked up via `texelFetch` with `gl_InstanceID`-derived offsets, and flagged that antialiasing requires computing a signed distance from the winding number evaluation rather than relying on MSAA. Their key concern is that no existing implementation combines Slug with GPU instancing at this scale in WebGL 2, so a standalone prototype with a single CodeGrid (~5000 glyphs) should validate performance before full integration.
